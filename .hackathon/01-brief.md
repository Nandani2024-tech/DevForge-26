# Brief for Antigravity: Secret Wards privacy firewall
- **Goal:** An offline, CPU-only, LLM-free Python CLI. `main.py --input DIR --output DIR` writes a PII-free mirror of messy Indian hospital records (EN/हिंदी/Hinglish) with exact medical values, one keyed pseudonym per patient, and safe quarantine.
- **Build:** R1 raksha.toml + run contract (sanitized/, report.json, records.jsonl) · R2 multi-encoding ingest + quarantine, never crash or copy raw · R3 same paths, format, header, row/key shape, UTF-8 · R4 valid FHIR R4, references resolve · R5 column/key PII by meaning · R6 ID and phone regexes (Aadhaar, ABHA, PAN, MRN, insurance, email, phones, Devanagari digits) · R7 names in 3 scripts (labels, honorifics, S/o-W/o-C/O, transliteration, context) · R8 keep Dr., doses, 1-0-1, C/O complaint, K/C/O, eponyms, wards · R9 file names, headers, keys, metadata, base64 · R10 cross-file/script linking, no homonym merges, null when weak · R11 HMAC(RAKSHA_SECRET) pseudonym inside each record + records.jsonl · R12 per-patient secret date shift, exact intervals · R13 truthful age bands, village->district, PIN prefix · R14 k-anon rare-cell suppression + measured risk · R15 honest report.json/records.jsonl · R16 exit 0 only when complete · R17 no PII or secret in stdout, stderr, logs, temp, errors · R18 AES-GCM intermediates, keys out of data · R19 byte-deterministic · R20 < 15 min, < 4 GB, 2 CPU, offline, cross-platform peak RSS (psutil) · R21 never touch input · R22 no dev-specific strings · R23 no LLM/large models · R24 README · R25 2-page PDF.
- **Do not build:** UI in the run path (an optional offline demo view under tools/ is allowed only after all MUST items pass); OCR/PDF/JPG/XML parsing (quarantine); ZKP pipeline; LLMs or large models.
- **Data:** inputs are csv/tsv/json/FHIR/txt in UTF-8, BOM, UTF-16, cp1252, plus junk (pdf, jpg, xml, empty, truncated, 1,500-deep JSON, JSON behind .csv). Output contract: kit docs/SPEC.md sec 4-6. `loc` = input locator: `row:N` (0-based, no header), JSON pointer, or `doc`. Env: RAKSHA_SECRET (never write it). Schemas and counts: .hackathon/01-ps.md sec 4. Never copy dev names/IDs into code.
- **Quality bar (check_dev):** leak <= 3% overall, <= 5% deva/hinglish, 0% per hidden channel, 0 canaries; medical kept >= 97%; link precision >= 0.95, F0.5 >= 0.85, 0 wrong merges; < 60 s, < 512 MB on dev; validate_output CONTRACT OK; check_submission READY TO SUBMIT.
- **Traps to avoid:** overfitting to dev strings; over-redaction; global or unkeyed shifts/hashes; transitive name-only clustering; pseudonym missing from the record; leaks in logs/errors/temp; set/time-order nondeterminism; Windows-only paths or RSS code.
- **Scope:** MUST (V0): R1, R2, R3, R5, R6, R7, R8, R9, R10, R11, R12, R13, R15, R16, R17, R19, R20, R21, R23 · NICE (V1, in order N1-N9): R4, R14, R18, R22, R24, R25 · DROP: none · Targets: O(bytes) per file; linkage O(R·α(R)); dev run < 20 s, peak RSS < 512 MB; limits 900 s / 4 GB / 2 CPU; V0 gate: CONTRACT OK + beats the starter on every check_dev number except base64 + READY TO SUBMIT.
