feat(R5,R8): classify columns by value shape when headers are renamed

Unknown or renamed headers and keys no longer hide PII: a capped
per-column vote over value shape, address cues, age shape and run-time
name evidence decides the column, and an ID-shaped column overrides a
facility-style header only when its values are non-medical and
high-cardinality. No word lists were added; every rule uses existing
locked vocabulary or value shape.

Changes:
- columns: shape/address/age/name-evidence vote, adjacent address-part
  promotion, per-column ID override with min-values and distinct-count
  rule, non-patient ID columns found by per-patient variation
- slots: column slot priorities computed once per file, named slot
  priority constants, JSON slots use per-key decisions only
- pipeline: per-column and per-key decisions made before the row and
  leaf loops in both passes; free-text keys skip address-shape checks
- patterns, names: medical-value check built on the existing protect
  mask; strict ID shape without the postal-code kind
- dates: DD.MM.YYYY dates parsed and shifted with their format kept
- config: named voting, cardinality and slot-priority constants
- tests: renamed-header, over-redaction, tie-break, per-column call
  count and whole-pipeline scaling cases with invented values
