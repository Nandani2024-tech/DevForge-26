fix(R12,R13): decide text date order from run evidence, band valid ages

A text whose dates never show a day above 12 was read day-first, so
month-first notes lost their intervals and two shifts left the policy
range. The order now comes from the strongest evidence in the run. An
age outside the valid range is no longer banded or left raw: it gets
the age placeholder, so no band can exclude the true age.

Changes:
- dates: order vote counts, certain vs ambiguous date evidence, and a
  resolver that takes the first source with a decisive vote
- pipeline: per-text order from own dates, then dates of records
  linked to the same patient, then files of the same export family,
  day-first only without evidence
- generalisation: signed and out-of-range ages become [AGE] in fields,
  integers and free text; MIN/MAX valid age in config
- cleanups: slots reuses the column name-word set, names reuses the
  shared protect regex
- tests: R11-R13 acceptance against dev truth (fails without the kit),
  linked-record and export-family order, invalid ages
